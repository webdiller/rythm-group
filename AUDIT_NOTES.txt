1. БЕЗОПАСНОСТЬ (пентест-угол)
--------------------------------------------------------------------------------

Критично:
- Middleware не проверяет JWT, только наличие cookie auth_token (middleware.ts).
  Подойдёт любая непустая строка. Защита на API через requireAuth, но UI и клиентский
  бандл для /dashboard/* доступны при поддельной cookie.

- Cookie выставляется из JS без флагов (app/dashboard/login/page.tsx): нет HttpOnly,
  Secure, SameSite. Токен доступен скриптам — риск при XSS. Предпочтительно: httpOnly
  cookie через ответ сервера (Set-Cookie из Route Handler после логина).

- JWT_SECRET с дефолтом (lib/auth.ts): при забытом .env в проде токены подписываются
  известным секретом.

Высокий риск:
- ADMIN_USERS — пароли в открытом виде в env (lib/auth-env.ts). Утечка env = компромисс.

- Контактная форма: нет rate limiting / капчи — спам и DoS по SMTP.
  Логин без задержки/лимита — брутфорс (особенно для простых паролей в ADMIN_USERS).

- HTML письма собираются строками (app/api/contact/route.ts); поля в HTML без
  экранирования — риск инъекции в тело письма (зависит от клиента; лучше санитизация
  или текстовое письмо).

Средний:
- Логотипы/аватары как base64 в SQLite — раздувание БД, тяжёлые ответы.


2. DEVOPS И КАЧЕСТВО СБОРКИ
--------------------------------------------------------------------------------

- typescript.ignoreBuildErrors: true в next.config.mjs — ошибки TypeScript не блокируют
  прод-сборку.

- В package.json есть lint: "eslint .", но нет конфигурации ESLint в репозитории —
  скрипт может быть бесполезен или падать.

- Нет test / tsc --noEmit в скриптах.

- GitHub Actions (.github/workflows/deploy.yml): только SSH + git pull + docker —
  нет build/lint перед деплоем.

- Расхождение документации и пайплайна: DEPLOY_VPS.md описывает PM2 + nginx, workflow —
  docker compose. Нужен один каноничный способ деплоя.


3. ОРГАНИЗАЦИЯ КОДОВОЙ БАЗЫ
--------------------------------------------------------------------------------

Сильные стороны:
- Разделение schemas / services / api routes в целом понятное.
- Повторяющиеся операции с контентом идут через Zod + сервисы.

Слабые места:
- Имя проекта: папка project-kwork-landing, npm rythm-group — путаница.

- Дублирование: hooks/use-mobile.ts и components/ui/use-mobile.tsx (и похожие с toast).

- Смешение .jsx и .tsx (LightRays.jsx) без явной причины.

- lib/db.ts — тонкая прокси к lib/db/index.ts.

- runSeed вызывается из getDb(): при каждом холодном старте проверки «есть ли строки»;
  лучше отделить миграции/сид от runtime-подключения (отдельная команда db:seed уже есть).

- В middleware верифицировать JWT (или отказаться от cookie-gate и полагаться на
