2. БАЗА ДАННЫХ (DRIZZLE / SQLITE)
================================================================================

2.1. Таблица blog_categories (категории)
    Поля (минимум):
    - id: integer PK autoincrement
    - slug: text NOT NULL UNIQUE — латиница, kebab-case, для URL
    - name_ru, name_en: text NOT NULL
    - order_index: integer NOT NULL default 0 — порядок в фильтре и UI
    - deleted_at: integer NULL (unix timestamp) или аналог — soft delete (ТЗ п. 3.1, 7)
    - created_at: по аналогии с created_at в проекте (common-fields)

    Индексы: UNIQUE(slug) среди не удалённых — в SQLite проще фильтровать deleted_at IS NULL в приложении.

2.2. Таблица blog_posts (записи)
    Поля (минимум):
    - id: integer PK autoincrement
    - category_id: integer NOT NULL → FK blog_categories.id (onDelete: RESTRICT или запрет удаления
      «жёсткого»; при soft delete категории каскадно помечать посты — логика в сервисе/API)
    - slug: text NOT NULL — уникальность в паре (category_id, slug) для URL /blog/[category]/[post]
    - title_ru, title_en: text NOT NULL
    - excerpt_ru, excerpt_en: text NOT NULL (краткий анонс)
    - body_html_ru, body_html_en: text NOT NULL — HTML из TipTap (после санитизации)
    - cover_image_url: text NULL — одна обложка (URL в S3/CDN); уже заложено в UI моков
    - status: text NOT NULL — 'draft' | 'published'
    - published_at: integer NOT NULL (unix) — дата публикации; для черновика можно дублировать created_at
      или NULL с правилами в коде (ТЗ: по умолчанию дата создания)
    - created_at, updated_at: по принятой в проекте схеме

    Уникальный ключ: (category_id, slug) среди записей с deleted_at IS NULL (enforce в приложении или
    частичный уникальный индекс, если поддерживается).

    - deleted_at: integer NULL — soft delete (ТЗ при удалении категории вместе с записями)

2.3. Расширение site_settings (или отдельная таблица affiliate_settings)
    Для ТЗ п. 2.1 (переключатели дат и видимость блоков):
    - blog_show_dates: boolean (показывать даты в блоге на публичном сайте)
    - affiliate_show_blog_block: boolean (мини-блог на странице /affiliate, до 6 записей)
    Остальные флаги Affiliate — по макету, вне скоупа только-блог.

2.4. Миграции / push
    - Добавить таблицы в lib/db/schema.ts, relations в Drizzle.
    - Выполнить drizzle-kit push (или миграции), обновить lib/db/seed.ts при необходимости начальными
      категориями (Новости, Кейсы, Статистика, Мемы — согласовать с заказчиком).

3. API (ROUTE HANDLERS)
================================================================================
Паттерн: как существующие /api/content/* — проверка Bearer JWT, валидация (zod), ответы JSON.

3.1. Категории
    GET    /api/content/blog/categories          — список (админ: включая удалённые или флаг ?includeDeleted)
    POST   /api/content/blog/categories        — создать (slug unique, валидация kebab-case)
    PATCH  /api/content/blog/categories/[id]   — обновить (имена, slug при смене — осторожно с URL)
    DELETE /api/content/blog/categories/[id]   — soft delete категории + soft delete всех постов категории
                                                (ТЗ); тело/параметр confirm: true после UI-подтверждения

3.2. Записи
    GET    /api/content/blog/posts             — список для админки: фильтр ?categoryId=, ?status=
    GET    /api/content/blog/posts/[id]        — одна запись (админ)
    POST   /api/content/blog/posts             — создать (черновик/опубликовано)
    PATCH  /api/content/blog/posts/[id]        — обновить, смена статуса (опубликовать / снять)
    DELETE /api/content/blog/posts/[id]        — soft delete

3.3. Публичное API (без мутаций, можно без JWT или с кэшем)
    GET    /api/public/blog/categories         — только не удалённые, порядок order_index
    GET    /api/public/blog/posts              — только status=published, deleted_at IS NULL;
                                                опционально ?categorySlug=; сортировка: published_at DESC,
                                                tie-breaker created_at DESC (ТЗ п. 3.2)
    GET    /api/public/blog/posts/by-slug      — query categorySlug + postSlug → одна запись
      ИЛИ вложенный маршрут по соглашению команды.

3.4. Загрузка файлов (обложка / медиа в теле)
    POST   /api/content/blog/upload (или общий /api/content/media) — проверка размера ≤10 МБ, MIME
    jpg/png/webp/gif; загрузка в Yandex Object Storage (S3 API); возврат публичного URL.
    Секреты: env (ключи S3), не коммитить.

3.5. Санитизация HTML
    При POST/PATCH постов: прогон body_html_ru/en через санитайзер (например, isomorphic-dompurify или
    sanitize-html на сервере) с белым списком тегов под TipTap (п. 3.3, п. 6 ТЗ).
