# Техническое задание: раздел Affiliate + мини-блог (финальная версия)

**Основание:** файл `RG_ Landing TT.txt` (вопросы/ответы заказчика + описание ТЗ).  
**Статус:** финальная согласованная версия на основе заполненного файла `RG_Affiliate_QUESTIONS.txt`.

---

## 1. Цели и границы проекта

### 1.1. Бизнес-цели

- Показать **кейсы с партнёрами** (GameDev / маркетинг): вишлисты, релизы, статистика, проекты.
- Дать **продающий контент**: почему работать с компанией и как связаться.
- Вести **ленту материалов** (мини-блог / блог) в духе «ленты новостей», с возможностью публиковать кейсы и другую информацию по разделу.
- Обеспечить **RU / EN** на уровне основного лендинга: пользователь переключает язык и получает согласованные тексты.

### 1.2. Вне скоупа (по ответам заказчика)

- Планировщик отложенной публикации **не обязателен** (достаточно черновиков и ручной публикации).
- Массовый импорт материалов из внешних систем **не планируется** (максимум — ручное добавление текста, ссылок, копирайта, медиа).

### 1.3. Связь с текущим сайтом

- Используется **существующая админ-панель**; добавляется отдельный раздел настройки **Affiliate** (и блога — см. раздел 6).
- Два дополнительных блока на странице Affiliate (см. раздел 4.3) должны **синхронизироваться с контактами основного лендинга** там, где это указано, без «рассинхрона» по умолчанию.

---

## 2. Информационная архитектура и маршруты

### 2.1. Страница Affiliate (лендинг раздела)

| Элемент              | Описание                                                                                        |
| -------------------- | ----------------------------------------------------------------------------------------------- |
| URL                  | `/affiliate`                                                                                    |
| Навигация            | Согласована с основным лендингом; возможность секций/якорей под блоки (в т.ч. под будущий FAQ). |
| Пункт в главном меню | Не требуется.                                                                                   |

**Блоки страницы (сверху вниз):**

1. **Герой / продающий блок**
   - Суть партнёрства.
   - Две кнопки:
     - «Подать заявку» -> ведет к форме на странице `/affiliate`;
     - «Подробнее» -> ведет к секции с описанием сути на странице `/affiliate`.
   - В админке: возможность **скрыть блок целиком**.

2. **Варианты сотрудничества**
   - Несколько карточек/пунктов с заголовком и описанием.
   - Предусмотренные типы по ТЗ: вишлисты; реклама; % с продаж; полное продвижение (фикс с продаж).
   - Неактуальные варианты **скрываются в админке** (мягкое скрытие).
   - RU/EN для всех видимых полей.

3. **Кейсы (превью)**
   - Список кейсов с возможностью «Показать ещё».
   - У каждого элемента в ленте превью: **обложка (картинка игры)**, **название**, **дата публикации** (если включено отображение дат — см. 3.4), **метрика вишлистов** (или аналог из ТЗ).
   - По клику — **страница одного кейса** (см. 2.2).

4. **Блок с внешними ссылками (Steam и т.п.)**
   - По смыслу ТЗ: при действии пользователь переходит на **страницу Steam разработчика/издателя** (или иной URL).
   - Структура данных: список карточек (логотип/изображение, подпись RU/EN, внешняя ссылка).

5. **FAQ**
   - Темы: предоплатa, сроки публикаций, оплата и т.д.
   - Редактирование: отдельные пары вопрос-ответ в админке, RU/EN отдельно.
   - Поля FAQ: `question_ru`, `answer_ru`, `question_en`, `answer_en`, `sort_order`.
   - Поддержка изменения порядка через drag-and-drop.

6. **Мини-блог (врезка на главной Affiliate)**
   - До **6** последних **опубликованных** записей блога: заголовок, дата (если включено отображение дат), краткий текст, ссылка на полную запись.

**Глобальные переключатели в админке Affiliate:**

- Видимость отдельных **крупных блоков** страницы (минимум: продающий блок, блок мини-блога, при необходимости — другие согласованные с заказчиком).
- Режим отображения **дат**: отдельные переключатели для блога и для кейсов (**с датами / без дат**).

### 2.2. Детальная страница кейса

При открытии кейса пользователь видит:

- Заглавное изображение игры.
- Краткое описание игры.
- Галерею/блок скриншотов **публикаций** (реакции, просмотры — как в референсе).
- Текст: за сколько дней собрали вишлисты; скрин статистики Steam (и при необходимости ссылка «как в X»).
- Медиа и копирайт задаются из админки; формат «как пост в Telegram» — **блоки текста и медиа**, линейная подача.

URL кейса: `domain.com/cases/[slug]`.  
Кейсы и блог — разные сущности (кейс не является записью блога по умолчанию).

### 2.3. Блог (маршруты по ТЗ)

| Маршрут                   | Назначение                                                                                                |
| ------------------------- | --------------------------------------------------------------------------------------------------------- |
| `/blog`                   | Все опубликованные записи; сверху фильтр по категориям; **без пагинации** — полный список.                |
| `/blog/[category]`        | Все записи выбранной категории; крупный заголовок категории.                                              |
| `/blog/[category]/[post]` | Одна запись: заголовок, дата (если включено), категория со ссылкой назад, полный текст с форматированием. |

Язык: контент переключается вместе с **глобальным переключателем языка сайта** (как на основном лендинге).

## 3. Данные: блог

### 3.1. Категории

- Название **RU** и **EN**.
- **Slug** («краткое имя») для URL — уникальный, латиница, kebab-case.
- **Порядок** отображения в фильтре и на странице категорий.
- Операции в админке: список, создание, редактирование, удаление.
- При удалении категории удаляются все записи этой категории (soft delete), с обязательным предупреждением и подтверждением в интерфейсе.

**Категории по ответам заказчика:** Новости, Кейсы, Статистика; возможно «Мемы». Список начальных категорий согласовать при запуске контента.

### 3.2. Запись блога

- Одна запись → **ровно одна категория** (по ТЗ).
- Поля: заголовок RU/EN; краткий анонс RU/EN; полный текст с форматированием RU/EN.
- Дата публикации по умолчанию — текущая дата создания записи.
- Статус: **черновик / опубликовано** (пользователю статус не показывается).
- Сортировка «свежести» на главной и в `/blog`: по дате публикации (новые выше), при равенстве — по дате создания (новые выше).

### 3.3. Редактор контента

- «Удобный текстовый редактор» с поддержкой: абзацы, подзаголовки, списки, выделения, ссылки.
- Используется редактор **TipTap**.
- Формат хранения контента должен соответствовать интеграции TipTap; на сервере обязательна санитизация пользовательского HTML/разметки.

### 3.4. Медиа в записях

- Возможность добавлять **медиафайлы** (как в постах Telegram по смыслу ТЗ).
- Лимит файла: до **10 MB**.
- Поддерживаемые форматы: `jpg`, `png`, `webp`, `gif`.
- Хранение: **S3-совместимое хранилище (Yandex Object Storage)**.

## 4. Данные: блоки Affiliate «контакты»

### 4.1. Блок 1 — синхронизация с основным лендингом

- Подтягивает **те же соцсети и контакты**, что и на главной (единый источник правды в админке или реюз существующих сущностей контактов).
- Цель: пользователь может перейти на те же каналы с Affiliate, что и с главной, без расхождения данных.

### 4.2. Блок 2 — контакты для партнёров

- Отдельный набор полей **специально для Affiliate** (контакт «для партнёров»).
- RU/EN при необходимости по тем же правилам, что и остальной сайт.
- Кнопка «Подать заявку» использует форму как на главной странице; отправка идет на email, указанный в админке.

### 4.3. Видимость

- В админке: можно **скрывать блоки по отдельности** и **оба вместе** (как в ответе заказчика).

## 5. Админ-панель

### 5.1. Раздел «Affiliate»

- Настройки видимости **блоков лендинга** Affiliate (перечень блоков — финализировать по макету).
- Управление **вариантами сотрудничества** (CRUD + скрытие).
- Управление **кейсами** (структура полей — по разделу 2.2 и ответам на вопросы).
- Управление **ссылками Steam / издателей** (блок 4 на лендинге).
- **FAQ**: согласно ответу на открытый вопрос.
- Переключатели **дат** (раздельно: блог и кейсы).
- Блоки контактов (4.1–4.3).

### 5.2. Раздел «Блог»

- Пункт меню **«Блог»**.
- Подразделы: **Категории**, **Записи**.
- Записи: фильтр по категории; колонка статуса черновик/опубликовано; создание/редактирование/снятие с публикации.
- Доступ: одной роли **«администратор»** достаточно для управления всем контентом Affiliate и блога.

## 6. Нефункциональные требования

- Визуал: те же шрифты, отступы, кнопки, что у текущего сайта; карточки записей; адаптив.
- Производительность: изображения не раздувать ответы API; кэширование статики — по текущей инфраструктуре.
- Безопасность: авторизация для всех мутаций контента; валидация входных данных; санитизация HTML при rich-text.
- SEO: отдельные `meta title` и `meta description` для страницы Affiliate и для каждой страницы записи блога.
- Аналитика: отдельная интеграция не требуется в рамках данного ТЗ.

---

## 7. Критерии приёмки

- Страница Affiliate доступна по согласованному URL; все описанные блоки заполняются из админки; скрытие блоков работает.
- Кейс открывается на отдельной странице с полным контентом по ТЗ.
- `/blog`, `/blog/[category]`, `/blog/[category]/[post]` работают; фильтр по категориям без пагинации; RU/EN.
- В админке доступны разделы Affiliate и Блог с перечисленными операциями.
- Два контактных блока ведут себя согласно п. 4; переключатели видимости работают.
- Кнопки первого блока ведут в согласованные секции/форму на `/affiliate`.
- При удалении категории блога пользователь видит предупреждение; удаление категории и её записей выполняется как soft delete.
- Метаданные SEO задаются и применяются для Affiliate и страниц блога.

## 8. Принятые ключевые решения

- URL раздела: `/affiliate`, без отдельного пункта в главном меню.
- Кейсы и блог разделены на уровне сущностей и управления.
- URL кейса: `domain.com/cases/[slug]`.
- FAQ хранится как список Q/A RU/EN с drag-and-drop сортировкой.
- Даты отображаются отдельными переключателями: для блога и для кейсов.
- Редактор статей: TipTap.
- Медиа: до 10 MB, `jpg/png/webp/gif`, хранение в Yandex Object Storage (S3).
- Удаление категории блога: вместе с записями, через soft delete и подтверждение.
- SEO: отдельные meta title/description для Affiliate и блога.
- Роли: одна роль администратора.
