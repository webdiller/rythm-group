### Мини‑блог — техническое задание

#### Цель

**Цель мини‑блога**  
Реализовать многоязычный (RU/EN) мини‑блог с отдельной страницей и вложенными маршрутами, который:

- отображает до **6 последних постов** на главной странице;
- предоставляет общий список постов и списки по категориям на `/blog` и `/blog/[categorySlug]`;
- отображает отдельную страницу поста `/blog/[categorySlug]/[postSlug]`;
- управляется через существующую админку, с возможностью в будущем добавить импорт.

---

#### Краткое описание

**Мини‑блог** — это набор страниц и админ‑интерфейсов для создания, редактирования и отображения новостных/экспертных публикаций.

Каждый пост:

- принадлежит **одной категории**;
- имеет **slug**, зависящий от категории (путь `/blog/[categorySlug]/[postSlug]`);
- содержит **rich text‑контент в формате HTML‑строки** на русском и английском языках.

---

#### Маршруты фронтенда

- **`/blog` — список всех постов**
  - Выводит все опубликованные посты без пагинации.
  - Сортировка: по `publishedAt` (дата публикации) по убыванию — самые новые сверху.
  - Фильтрация по категориям:
    - список категорий (табы/чипы/селект);
    - состояние «Все категории» (показывает все посты);
    - смена категории фильтрует список без перезагрузки страницы.
  - Карточка поста:
    - заголовок текущей локали;
    - дата публикации;
    - название категории;
    - краткий текст (`excerpt`);
    - ссылка на `/blog/[categorySlug]/[postSlug]`.

- **`/blog/[categorySlug]` — посты выбранной категории**
  - Отображает только опубликованные посты выбранной категории.
  - Заголовок страницы — локализованное название категории.
  - Те же карточки постов, что на `/blog`.
  - Опциональная навигация: «Все категории», другие категории.

- **`/blog/[categorySlug]/[postSlug]` — страница поста**
  - Отображает:
    - заголовок (RU/EN по текущей локали);
    - дату публикации;
    - категорию (с ссылкой на `/blog/[categorySlug]`);
    - rich text‑контент поста для текущей локали:
      - хранение в БД как HTML‑строка (`content_ru_html`, `content_en_html`);
      - вывод с безопасным рендером.
    - опционально — блок «ещё статьи категории» или «Назад к блогу».
  - SEO:
    - `<title>` и `<meta description>` на основе `title` и `excerpt` текущей локали.

- **Блок мини‑блога на главной (`Home`)**
  - Отдельная секция на лендинге.
  - Заголовок и подзаголовок через локализацию (`t.blog.title`, `t.blog.subtitle`).
  - Выборка до **6 последних опубликованных постов** (по дате убыванию).
  - Карточка:
    - заголовок, дата, краткий текст;
    - ссылка «Читать полностью» → `/blog/[categorySlug]/[postSlug]`.
  - Кнопка «Смотреть все» → `/blog`.

---

#### Структура данных

- **Категория поста (`BlogCategory`)**
  - `id: number`
  - `slug: string`
    - уникальный идентификатор категории в URL (`/blog/[categorySlug]`);
    - латиница, без пробелов.
  - `name_ru: string`
  - `name_en: string`
  - `order_index: number` — порядок отображения в списках.

- **Пост (`BlogPost`)**
  - `id: number`
  - `category_id: number` — связь с `BlogCategory` (обязательна).
  - `slug: string`
    - используется вместе с `categorySlug` для построения URL `/blog/[categorySlug]/[postSlug]`;
    - уникальность slug гарантируется на уровне пары `(category_id, slug)` (одинаковые slug в разных категориях возможны).
  - `title_ru: string`
  - `title_en: string`
  - `excerpt_ru: string` — краткий анонс.
  - `excerpt_en: string`
  - `content_ru_html: string` — rich text в виде HTML‑строки.
  - `content_en_html: string` — rich text в виде HTML‑строки.
  - `publishedAt: Date` — дата публикации.
  - `isPublished: boolean` — флаг публикации.
  - `order_index?: number` — опционально, если понадобится ручная сортировка вдобавок к дате.

---

#### API‑роуты (публичный контент)

- **Категории**
  - `GET /api/content/blog/categories`
    - возвращает массив `BlogCategory[]` для отрисовки фильтров и навигации.

- **Посты список**
  - `GET /api/content/blog/posts`
    - Параметры:
      - `categorySlug?: string` — опциональная фильтрация по категории;
      - `limit?: number` — опциональный лимит (например, `limit=6` для главной).
    - Логика:
      - выбираются только записи с `isPublished = true`;
      - сортировка по `publishedAt DESC`;
      - при наличии `categorySlug` — фильтрация по категории.
    - Возвращаемые данные:
      - `id`;
      - `category` (slug + названия);
      - `slug`;
      - `title_[locale]`;
      - `excerpt_[locale]`;
      - `publishedAt`.

- **Пост детально**
  - `GET /api/content/blog/posts/[categorySlug]/[postSlug]`
    - возвращает один опубликованный пост с:
      - данными категории;
      - полным HTML‑контентом (`content_[locale]_html`);
      - метаданными (`title`, `excerpt`, `publishedAt`).

---

#### Админка (управление контентом)

- **Раздел «Блог» в `/dashboard`**
  - Новый пункт меню «Блог» (RU/EN).
  - Внутри — два подраздела:
    - **Категории**
      - список категорий:
        - `name_ru`, `name_en`, `slug`, `order_index`;
      - создание, редактирование, удаление;
      - автогенерация `slug` из имени (с возможностью ручной правки);
      - валидация уникальности `slug`.
    - **Посты**
      - список постов:
        - фильтр по категории;
        - индикатор публикации (`isPublished`);
        - дата публикации;
      - форма создания/редактирования:
        - выбор категории (`category_id`);
        - `title_ru`, `title_en`;
        - `slug` (автогенерация, возможность редактировать; уникальность в рамках категории);
        - `excerpt_ru`, `excerpt_en`;
        - `content_ru_html`, `content_en_html` (визуальный rich text‑редактор, сохраняющий HTML);
        - `publishedAt`;
        - `isPublished`;
        - опционально `order_index`;
      - удаление поста.

- **Импорт (на будущее, опционально)**
  - В текущем ТЗ:
    - предусмотреть, что в будущем может быть добавлен импорт постов/категорий через отдельный эндпоинт и UI;
    - текущая реализация не обязана иметь импорт, но архитектура не должна этому мешать.

---

#### Общие и нефункциональные требования

- **Локализация**
  - Поддержка RU/EN:
    - UI‑тексты — через существующий `LocaleProvider` и словарь (`t.blog.*` и т.п.);
    - контент постов и категорий — раздельные поля для RU и EN.
  - На фронтенде использовать текущую локаль для выбора нужных языковых полей (`title_ru`/`title_en` и т.д.).

- **Стиль и UX**
  - Использовать существующую дизайн‑систему:
    - Tailwind‑классы, shadcn/ui‑компоненты (`Card`, `Button`, `Tabs`, `Input`, `Textarea`, `Form` и т.п.).
  - Блоки блога должны органично встраиваться в текущий стиль сайта.
  - Сетка карточек должна корректно адаптироваться под разные разрешения (мобильные/десктоп).

- **Производительность**
  - На главной:
    - запрашивать только до 6 постов.
  - На `/blog` и `/blog/[categorySlug]`:
    - отсутствует пагинация, но структура запросов и рендер должны позволять работать с разумным количеством постов без деградации.
  - Кеш и стратегия загрузки — по аналогии с текущими `/api/content/*` (например, `cache: "no-store"` для быстрых обновлений, если это важно).
